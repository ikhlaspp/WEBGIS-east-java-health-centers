# Scraping resilience implementation and evidence

24 October 2026. Shared transport: python/gis_pipeline/etl/http_client.py. Shared batch reconciler: python/gis_pipeline/etl/batch.py. CLI wrappers live in scripts/etl. Existing PDF, JSON and ZIP-range adapters use this transport; no competing retry implementations remain.

HTTP identity includes source ID, explicit edition, exact URL parameters, request headers and expected status. Cached responses have immutable raw SHA-256 receipts and atomic request indexes. Every hit rechecks the raw hash, size and current validator; tampering fails without silently replacing evidence. Different periods/parameters cannot hit the same request index. Explicit refresh is supported. Live BIG consistency queries and the HDX catalogue bypass cache; ZIP ranges are never cached/persisted as if they were complete sources.

Transport has a ten-second connection/TLS bound, sixty-second read bound, and a fifteen-minute request deadline. Transient transport failures and 429/500/502/503/504 get at most three attempts with 5/15-second backoff plus jitter. Both numeric and HTTP-date Retry-After are honored. Delays beyond the deadline become pending with due_at; malformed delay instructions require review. 401/403/404 and schema failures do not retry. Public-source credentials are refused and provider error URLs/messages are not copied into batch errors. In-worker requests are serialized and paced at least one second apart per host. Run one acquisition worker for this local CLI stage; distributed queue coordination belongs to later application/database work.

Local batches use an OS file lock released on process exit, an identity that includes input hash/source/release/version/operation/parameter hash, atomic page files and checkpoints. Each resumed page is checksum-verified. Changed input/release/schema expectations require a distinct batch. Source IDs must be unique across pages; every expected page and ID must appear; next-page markers must match and end explicitly. Accepted+quarantined+aggregate counts must equal raw count. Empty, duplicate, missing, changed-header or truncated batches never succeed. Failed candidate pages remain private evidence. A fifteen-minute chunk budget stops before starting more pages; callbacks must use the bounded transport. Retry-After remains enforced on early resume. These are local acquisition safeguards, not a claim that future database leases/outbox/release publishing have been implemented.

Actual CLI checks: downloading official HDX metadata once produced cache_hit=false and attempts=1; the second run produced cache_hit=true and attempts=0 with the same 15413-byte response hash. A real integration check also read ZIP header and end-directory ranges with the shared client and a stable ETag. The committed synthetic two-page batch passed with two accepted rows and an explicit terminal marker. The first live HTTP check exposed a Windows closed-socket condition after buffered data had already arrived; the client now avoids reconfiguring a closed socket, with a regression test and successful live retest.

Focused tests cover transient exhaustion, timeout backoff, Retry-After seconds/date/deferred scheduling, non-retriable permissions/history, query redaction, cache corruption and edition/parameter separation, schema revalidation, the closed-socket regression, interrupted resume, duplicate pages/IDs, changed headers, empty results, missing IDs, count reconciliation, input/release changes, checkpoint tampering, concurrent writers and chunk deadlines. Passing acquisition does not imply data-quality acceptance; that flag remains false even with quarantined rows accounted for.

Reproduce: python -m pytest tests/python/test_scraping_resilience.py -q. For the CLI: python scripts/etl/batch.py --spec tests/data/wf-060/batch.json --checkpoint data/staging/batches/synthetic-check.json. Actual final regression results are recorded in checkpoint.json. Raw responses, locks and checkpoints stay ignored/private. Archives was not changed.
