# Published reference API — 2026-10-25

Implemented GET /api/v1/releases, /api/v1/regions and /api/v1/sources with Laravel resources and strict query allowlists. ReleaseContext resolves the active pointer once when release_id is absent, validates a published release and matching succeeded/default run, and binds all subsequent reads to that release/boundary edition. Explicit draft/withdrawn/unknown IDs and wrong runs return404. No active dataset returns503/NO_PUBLISHED_RELEASE; an empty public release catalog remains a truthful200 with an empty list.

Every data request runs in a transaction with SET LOCAL ROLE gis_runtime. Only allowed public columns are selected; private source paths, raw records, source hashes and audit identities are absent. Region choices use exact parent and boundary membership. Source catalog entries must be referenced by the selected release or its boundary set. Responses retain release/run/boundary, source periods, coordinate counts, limitations and UTC generation time. Unknown stored eligible counts remain null; verified and eligible are not conflated.

Query errors use the versioned error envelope with request ID. Unknown parameters400, invalid values422, inaccessible objects404, rate limit429 with Retry-After, and database errors503 without SQL/credentials. Success and error responses require cache revalidation; visibility is queried anew, so withdrawal is effective on the next request. The public limit defaults to60 requests/min/IP and is configurable through PUBLIC_API_RATE_LIMIT. It uses the configured Laravel cache; a shared persistent cache still must be selected during multi-instance hosting deployment. No Vercel/Supabase deployment claim is made.

Local: eight validation/envelope cases passed; seven real-database HTTP cases require CI. They exercise empty/no-active distinctions, draft guessing, published pagination, explicit runtime role, parent/edition isolation, safe source fields, wrong-run and withdrawal, and throttling. The CI application artifact includes reports/reference-api.json captured from actual synthetic HTTP responses. The documentation example is explicitly illustrative until that run is verified.

The runtime login must be permitted to SET ROLE gis_runtime; the API does not use an owner role for its reads. Actual live credentials and data remain pending. No user research release has been published by this implementation.
