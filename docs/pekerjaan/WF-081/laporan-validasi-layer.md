# Analysis result persistence and thematic layers — 2026-10-25

Implemented shared exporter python/gis_pipeline/analysis/export_layers.py, CLI scripts/analysis/export_layers.py, canonical SQL indicators, and internal AnalysisRunService. The shared resources/analysis-legends.json is the fixed-v1 source for Python output and backend validation. Metadata binds release, run, boundary, input revision/hashes, code/method, T/radii, source periods and coordinate eligibility. No deployment credentials or real research data were used.

Preparation reads a locked draft and computes indicators plus coverage from the database, not caller-provided values. Export validation independently checks the formulas (1e-9 tolerance), coverage areas/geometry, count partitions, monotonic radii and exact district/radius membership. Missing values remain null, zero retains its numeric class, and known-population/no-facility differs from missing data. Four layers include units, sources, periods, completeness and fixed colour classes. Display currently uses the explicit full-geometry fallback; it preserves every component and does not overwrite full analysis inputs. Simplified display optimization is not claimed here.

The exporter writes five immutable files and writes manifest.json last, only after verifying actual file bytes. Content hashes exclude generation time and output directory; individual artifacts retain byte hashes. Unsafe paths, duplicate receipts, missing artifacts and byte tampering are rejected. The sample manifest-analysis-run.json is a genuine local synthetic-fixture export (fixture-release/fixture-run), not a deployed research run. Its files are private under ignored .tools/wf081-synthetic-example.

Trusted persistence takes the release lock, recomputes source results and checks the prepared input revision/hash. It verifies manifest identity/content hash, exact file paths/digests, scientific rows, layer membership/geometry, exact numeric values, display values, source metadata and legend classes. It writes canonical DB results and artifact registrations in one transaction, then marks the run succeeded. Identical scientific inputs/parameters replay the existing run after rechecking its files. Failed validation or a middle DB error cannot leave a successful or partial DB run. Files already generated remain private if DB persistence fails; they are not published or registered as successful. Finished runs/results/artifacts are immutable; incomplete/stale runs cannot transition to succeeded.

This is an internal persistence component, not an operator authorization shortcut: worker/runtime receive no new write grants, and a restricted worker is denied direct persistence. The active-admin identity check supplements the privileged DB boundary. Token-bound lifecycle functions and authorized commands remain WF-086; no public mutation route was exposed. Whitelisted thematic artifacts are sanitized on registration after the field/value checks; the full results bundle stays private. Public visibility still requires a published matching release/run.
